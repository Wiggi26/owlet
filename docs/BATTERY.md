# Battery transition investigation

OWL-022's reported charging spike is not reproduced as an integration conversion defect. In `pyowletapi==2025.4.1`, the Sock parser copies V3 `REAL_TIME_VITALS.bat` to `battery_percentage` and `btt` to `battery_minutes`; V2 copies `BATT_LEVEL` to `battery_percentage`. The integration sensor returns finite numeric property values as received. It does not clamp, smooth, or hold battery values across polls.

The regression replays a wholly synthetic sequence through the real pinned parser and Home Assistant entities: 50% while not charging, a 100% charging transition, 50% while charging remains stable, then 50% after charging ends. Both the normalized property and displayed percentage follow each input. The tests also cover two-sock isolation, V2 percentage support and recovery, missing battery data, and charging availability. The percentage sensor remains available while charging; battery minutes are unavailable while charging. The retained V2 parser does not expose `battery_minutes`, so no V2 entity is created for it. Unknown charging keeps percentage visible and makes battery minutes unavailable. A missing battery value becomes `unknown`, with no zero substitution.

This establishes faithful exposure of the parser's input, not the source or reliability of a cloud/firmware transition. The synthetic spike does not establish that production Sock 3 firmware emits this pattern. No protocol evidence supports filtering it; live/manual observation is optional under issue #18 and was not performed for this offline investigation. No smoothing, filtering, or alarm behavior change is warranted by the evidence.

[`tests/fixtures/battery_transitions.json`](../tests/fixtures/battery_transitions.json) is authored synthetic test input, not a cloud capture. Its V3 values model the report for contract testing; its V2 values cover only fields supported by that protocol. Cloud API calls are mocked, network sockets remain blocked, and the pinned library parser runs normally in [`tests/test_battery_transitions.py`](../tests/test_battery_transitions.py).
